# 字库更新指南

本文说明如何更新应用的汉字数据(新增汉字、修正字形、刷新词库/释义)。

## 标准提示词(复制给 AI 助手即可)

**更新组词库**(拉最新 CC-CEDICT 重新生成):

```text
更新组词库:按 docs/字库更新指南.md 场景 B 执行——
跑 tools/build_words_dictionary.py,再跑 tools/split_reference_data.py 重拆参考分片,
然后 flutter test 验证 reference 契约,最后 release 构建 + 静态服务器让我抽查。
注意:Windows 用 py 启动器;cedict 下载如失败记得走本机代理。
```

**调整每字组词上限**(如 8→12):在 `build_words_dictionary.py` 后加 `--max 12`,后续步骤同上。

**词库提质/扩充**(词频排序、加成语等)属开发任务而非重跑管线,提示时写清需求,
并要求:新增字符必须重跑 `tools/build_font_subset.py`(否则 tofu)、
更新本文档与 `assets/data/LICENSE.md` 署名。

**吸收 hanzi-writer-data 新的笔顺修复**(推荐例行操作):

```text
升级字形数据:按 docs/hanzi-writer-data升级-2026-08-29.md 的流程——
下载最新 hanzi-writer-data 包到 tools/cache,跑 build_chars_dictionary.py 升级模式,
再跑 split_chars_data.py --shard-size 64 和 split_reference_data.py,
检查差异报告(count changed 非空需人工复核),最后 flutter test 全量。
```

## 标准更新流程

### ① 更新源头字库

**方式 A(推荐):hanzi-writer-data 升级模式**——增量吸收社区笔画修复,
字符集/元数据不动,npmmirror 直连无需代理:

```bash
curl -sL -o tools/cache/hwdata.tgz \
  "https://registry.npmmirror.com/hanzi-writer-data/-/hanzi-writer-data-2.0.1.tgz"
mkdir -p tools/cache/hwdata && tar -xzf tools/cache/hwdata.tgz -C tools/cache/hwdata

python3 tools/build_chars_dictionary.py \
  --hanzi-writer-data tools/cache/hwdata/package \
  --upgrade-from assets/data/chars_3500.json
```

脚本会打印 identical/svg changed/median changed/count changed 差异报告;
`count changed` 非空的字需人工复核(笔数变化会导致 strokeNames 不再合并)。

**方式 B:传统全量模式**(graphics.txt + dictionary.txt,路径或 URL):

```bash
python3 tools/build_chars_dictionary.py \
  --graphics https://raw.githubusercontent.com/skishore/makemeahanzi/master/graphics.txt \
  --dictionary https://raw.githubusercontent.com/skishore/makemeahanzi/master/dictionary.txt
```

产出约 9600 个 CJK 汉字条目(含笔画轮廓 SVG 与中轴线)。

### ② 依次重跑下游工具(顺序固定)

```bash
python3 tools/build_stroke_names.py      # 笔顺名称,覆盖 ~6800 字
python3 tools/build_words_dictionary.py  # 组词+带调拼音,~6100 字(儿童内容过滤)
python3 tools/build_definitions_zh.py    # 中文释义,~7400 字
python3 tools/split_chars_data.py --shard-size 64
                                        # ⚠️ 拆出 index + shards,漏跑则改动不生效
python3 tools/split_reference_data.py    # ⚠️ 拆参考分片,必须在 split 之后
```

调整分片粒度:先看候选统计再改
(`python3 tools/split_chars_data.py --candidates 64,96,128`),粒度对
首开解码量的影响与决策记录见 `docs/分片粒度决策-2026-08-26.md`。

首次运行会自动下载源数据到 `tools/cache/`(已加入 .gitignore):
`stroke-order-jian.json`(cnchar)、`cedict.txt.gz`(MDBG)、`xinhua_word.json`(pwxcoo)。
也可提前手动放入缓存目录以离线执行。

### ③ 验证

```bash
flutter analyze
flutter test
```

相关测试会自动把关:

| 测试 | 校验内容 |
|------|---------|
| `dictionary_data_validation_test.dart` | 全部分片条目结构:笔数一致、order 连续、SVG/中线非空 |
| `reference_assets_validation_test.dart` | 整包中间产物 + 参考分片的覆盖率、格式与分片归属契约 |
| `reference_data_test.dart` | 参考分片按字切片、同片共享读取、失败可重试 |
| `stroke_classifier_golden_test.dart` | 32 个样例字的官方笔顺名称回归 |
| `stroke_reveal_coverage_test.dart` | 揭示笔刷对真实字形边界的覆盖率 |

## 常见场景

### 场景 A:上游 MakeMeAhanzi 更新了字形/新增汉字

走上面完整流程即可(全量重建)。
可先在上游仓库搜索目标字确认是否存在:

- 存在 → 全量重建后该字的笔画动画、笔顺名自动就绪
- 不存在 → 目前无法自动生成(SVG 路径需手造),查询时会显示"未找到该汉字"

### 场景 B:只刷新组词或释义(字形不变)

跳过 ①,从对应工具开始跑,最后必须重跑 `tools/split_reference_data.py`
(参考分片是运行时产物,漏跑则改动不生效;`split_chars_data.py` 可跳过,
它只影响笔画分片与索引)。

```bash
python3 tools/build_words_dictionary.py   # 只更新组词
python3 tools/split_reference_data.py     # ⚠️ 重拆参考分片
flutter test test/reference_assets_validation_test.dart
```

### 场景 C:调整每个字的组词数量上限

```bash
python3 tools/build_words_dictionary.py --max 12
```

## 能力覆盖与降级行为

各数据集覆盖范围不同,**缺失时应用自动降级,不会报错**:

| 数据 | 来源 | 覆盖 | 缺失时的表现 |
|------|------|------|-------------|
| 字形/笔顺动画 | hanzi-writer-data(makemeahanzi 派生) | ~9600 字 | 显示"未找到该汉字" |
| 笔画名称 | cnchar-order | ~6800 字 | 几何分类器推断(`StrokeClassifier`) |
| 组词+拼音 | CC-CEDICT | ~6100 字 | "词库建设中,敬请期待"占位 |
| 中文释义 | 新华字典(pwxcoo) | ~7400 字 | 回退显示英文释义(examples 字段) |
